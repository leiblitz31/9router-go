# DoH Resolvers get a dedicated dashboard page

Summary: the sidebar gains a DoH Resolvers page next to Proxy Pools: the primary doh pool's status card (active/strict toggles, strategy, stored test verdict), a resolver table with per-resolver probe results and add/remove, one-click creation of the seeded default pool when none exists, and an opencode pin/unpin control that reads and writes providerStrategies through the settings API.

Why: a doh pool was manageable only as a type inside the Proxy Pools form, which spreads one job across a generic screen: the resolver list there is a free-text area with no per-resolver health, the provider pin lives on a different page, and nothing showed which endpoint an alias actually dials. The page needed the backend to serve two facts that have exactly one owner there — the seeded defaults (pool name, resolver list, alias → endpoint table) now come from GET /api/doh/defaults instead of a second copy in the frontend — and one diagnostic the aggregate pool test cannot provide: a pool passes that test when any single resolver answers, so POST /api/proxy-pools/{id}/test-resolvers grades every resolver on its own, in pool order, without storing a verdict.

Test report: New Go tests cover the exported DoHAliases accessor (completeness against the resolver's table, copy semantics so a caller cannot rewrite it) and both dashboard handlers (defaults serve the seeded constants; test-resolvers returns 404 for a missing pool, 400 for a non-doh pool, and grades refused loopback resolvers individually in order). The full Go suite passes with no regressions beyond the seven pre-existing baseline failures. The frontend builds clean under bun run build, and make vet-svelte reports no new findings over the ratchet baseline.
