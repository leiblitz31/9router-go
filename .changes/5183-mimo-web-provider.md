### Added — `mimo-web` provider (Xiaomi MiMo Studio web chat)

- New native executor for Xiaomi MiMo Studio (aistudio.xiaomimimo.com), alias `mw`: `internal/proxy/executor/mimo_web.go`, `mimo_web_client.go`, `mimo_web_stream.go`, registered in `init.go` and declared in `providers.go` / `registry_models.go` / `aliases.go` / `capabilities.go`. It is a distinct provider from the `xiaomi-mimo` API deployment — separate endpoint, credential and quota (§3.A).
- The turn is one POST to the Studio's v3 chat path answering an SSE event stream (`dialogId` / `message` / `usage` / `finish` / `error`); the UltraSpeed model routes to the fastchat gateway path, which is the only one that serves it. The credential is the captured Studio session (the `serviceToken`, `userId` and `xiaomichatbot_ph` cookies), accepted as a JSON object or a pasted Cookie header and presented the way the site's own browser presents it.
- Requests are flattened into the single query the web turn takes and opened as a fresh server-side conversation per request, so a stateless router request is self-contained; the conversation is then registered on the account like the page does. Thinking (default on, `reasoning_effort` passed through) and web search (opt-in, `auto`) map onto the turn's model config; a 429/5xx before the stream starts is retried inside a 60-second budget with a fresh msgId per attempt, because the upstream deduplicates on it.
- The web surface has no native tool channel and the executor does not synthesize one: `Tools` stays false in the capability rows. Context windows are the Studio's own published figures for the v2.6 line (1M); the v2.5 line publishes none and carries none.
- A copied serviceToken lives about a day and nothing here pretends otherwise: an upstream 401 surfaces as a failure telling the operator to capture a fresh session, and the platform's 461 restriction signal surfaces with its own message instead of being retried.
- Verified: unit tests for credential parsing (JSON and Cookie-header shapes), event-stream decoding into content/reasoning/usage, message flattening and per-model chat-path selection (`go test ./internal/proxy/executor/ -run Mimo`), plus full `internal/proxy/executor` and `internal/providers` suites passing. Live verification waits on the first captured Studio session.
